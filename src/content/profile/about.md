## 技術的スキル

フロントエンドの経験が長いため、要件定義・設計・環境構築・テストなど、専門レベルのデザイン以外の業務は全て可能です。複雑な機能の要件定義や、UI/UX の改善・提案には比較的自信があります。

一般的な Web アプリケーションで求められる機能であれば、品質も含めて実装できないものは少ないと考えています。WebGL など扱う機会が少ない技術や、AI・ブロックチェーンなど専門知識が必要なものは、調査しながらになります。

TypeScript / Next.js / React / GraphQL / CSS in JS（CSS 設計も可能）などが得意です。特に Next.js と GraphQL（Apollo）、状態管理まわりに詳しいです。新しい技術が使われていても、素早くキャッチアップして自走できると考えています。

サーバサイドは Node.js が得意ですが、Ruby / Python / PHP も使えます。Go は個人的に触っていたため、簡単な読み書きができます（AI を使えばスムーズに扱えます）。パフォーマンスチューニングや排他制御など、比較的難易度の高い部分は基本的なことができるレベルです（セマフォや RLS など、一般的に使われる方法は理解しています）。

インフラは、開発・運用に必要な知識に加えて障害原因の特定などを行え、Terraform も扱えます（k8s や DWH などは理解が浅いです）。

DDD、クリーンアーキテクチャ、CQS などの設計は何度か経験しており、理解しているレベルです。セキュリティも、一般的な Web アプリケーション開発に必要な知識はあると認識しています。

## その他のスキル

PRD・Design Doc・ADR などには比較的慣れていて、書くことに抵抗はありません。断片的な情報から解像度を上げていくような開発もできます。

本格的なスクラム開発を 2 年半ほど経験しており、スクラムの知見があります。

Redash などの分析基盤を使った運用や、本格的な A/B テストの経験があるため、基盤さえあれば、データを見ながら細かい要件を決めたり提案したりすることもある程度できます（手が空いたときに分析して issue を作っていました）。

また、DevOps（CI/CD）を一から構築したり、ドキュメント整備を推進したりした経験があります。開発フローの効率化やナレッジ共有など、チームを支える作業や、開発を円滑にするツールづくりといった縁の下の役割も楽しんで取り組めるほうだと考えています（困った経験が多いため、ナレッジ共有は重要だと捉えています）。

建築・土木（2 級建築士・測量士補相当の知識、3D パース）、会計（確定申告、請求書）、士業（登記、個人の税）まわりのドメインに比較的強いと思います。複雑なドメインでも、比較的素早くキャッチアップできると考えています。

## 性格

設計や技術選定では、認知負荷が低い設計とメジャーな技術を好む傾向が強いです。当たり前ですが、好奇心やキャリアよりもプロジェクトの成功率を優先し、不要なリスクを避けます。

慎重なほうで、開発スピードよりも品質や保守性を重視する傾向がありますが、状況に応じてビジネスと品質のバランスを取りながら開発できます。品質は「ユーザーの要求が満たされていて、保守性が致命的に悪化しない程度」を正しいと考えているため、完璧主義ではありません。

弱みは、マネジメント（タスクの振り分けなど）とコーチングです。コーチングはある程度できますが、得意分野ではありません（チームの規模や、メンバーのスキル・相性によります）。
