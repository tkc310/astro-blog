# 指示書を書く

実装の前に「何を作るか」を合意するためのスキル。コード（`src/`・`package.json` など）はこの段階で書かない。

## 手順

1. **読む**
   - `docs/specs/blog-replace.md`（全体の要件）と、関連する指示書・ADR・`rules/*.md`
   - `docs/improvement/backlog.md` の「決めること」に関係する項目
2. **調べる**
   - 使うライブラリ・サービスの今の版と機能を、リリースのタグや公式ドキュメントで確かめる。記憶の版を前提にしない（Astro 6 だと思っていたら 7 が出ていたことがある）
   - 移行元（`tkc310/microCMS_blog`）に関係するなら、旧リポジトリの実装を読む
3. **書く**: `docs/specs/<機能名>.md` に次の節を置く
   - 0. 目的（何を良くするか。数字で言えるなら数字で）
   - 対象ファイル・関係する ADR とルール
   - 仕様（表・箇条書き。画面・データ・URL・構造化データ）
   - 受け入れ基準（確かめられる文で）
   - 未決（決まっていないことと、決める人）
4. **判断を分ける**: 方針や値を決めたものは ADR に切り出し、指示書からは ADR を指す
5. **出す**: 指示書を `docs/README.md` の表に足し、`log.md` に 1 行記録する。`docs` の type でコミットして PR を作る

## 書き方

- 1 文を短く、「〜する」で書く。あいまいな形容詞ではなく、数字・名前・パスで書く
- 規則（必ず守ること）は `rules/*.md` に、理由は ADR に、作るものは指示書に置き、同じことを 2 か所に書かない
