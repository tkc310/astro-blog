# 改善ループ

このブログは「書く・見る → 気づく → 記録する → 直す → 再発を防ぐ → 振り返る」を回して育てます。
人が回しても、AI エージェントが回しても同じ手順になるよう、段階ごとに置き場所と道具を決めています。

```
   ┌──────────── 書く・見る（記事・プレビュー URL・本番・Web Analytics）
   │                    │ 気づく
   │                    ▼
   │   ┌─ 自動: make check / CI ───────┐   ┌─ 手動: Issue「改善提案」・会話 ─┐
   │   └───────────────┬────────────────┘   └───────────────┬──────────────┘
   │                   ▼                                     ▼
   │          docs/improvement/backlog.md（改善候補）
   │                    │ 直す（1 PR 1 改善）
   │                    ▼
   │   再発防止: スキーマ / 型 / テスト / 検査スクリプト / ルール文書 / スキル / ADR
   │                    │
   └──── docs/improvement/log.md に記録 ◀┘
```

## 1. 気づく

### 自動

雛形ができたら、次の仕組みを順に整えます（まだ無いものは [バックログ](./improvement/backlog.md) にあります）。

| 仕組み                         | タイミング                | 何を見つけるか                                                                    |
| ------------------------------ | ------------------------- | --------------------------------------------------------------------------------- |
| Content Collections のスキーマ | ビルド時                  | frontmatter の抜け・型の誤り・存在しないカテゴリの参照                            |
| `make lint`                    | コミット前・PR ごと（CI） | フォーマット・静的検査・型の誤り                                                  |
| `make typecheck`               | PR ごと（CI）             | `.astro` の型の誤り（`astro check`）                                              |
| `make test`                    | PR ごと（CI）             | JSON-LD・目次・URL の組み立てなど、振る舞いの退行                                 |
| 出力の検査                     | PR ごと（CI）             | ビルド結果の HTML に JSON-LD・canonical・OGP があるか、内部リンクが切れていないか |
| 旧 URL の検査                  | PR ごと（CI）             | 旧ブログの URL 一覧が 200 か 301 で返るか（移行後）                               |
| Lighthouse CI                  | PR ごと（CI）             | 性能・SEO・アクセシビリティの点数の低下                                           |
| Web Analytics                  | 本番で常時                | Core Web Vitals（LCP・CLS・INP）の実測値の悪化                                    |

### 手動

書いていて・読んでいて気づいたことは、GitHub の Issue テンプレート「改善提案」で起票するか、エージェントとの会話で伝えます。
どちらも最後は `docs/improvement/backlog.md` に 1 行で残します。

## 2. 記録する

改善候補は [`improvement/backlog.md`](./improvement/backlog.md) にまとめます（Issue があればリンク）。優先度は次の順で判断します。

1. 記事や URL を失う・壊す（記事の欠落、リンク切れ、旧 URL の 404、移行の取りこぼし）
2. 設計のルールの破れ（[`rules/`](../rules/)：SSG、クライアント JS、構造化データ）
3. 読者が受け取る品質（表示速度、読みやすさ、検索や AI での見つかりやすさ）
4. 開発・執筆体験（コマンド、検査、CMS、ドキュメント、エージェントの手順）
5. 見た目の好み

## 3. 直す

- 1 PR 1 改善。大きいものは分割し、残りをバックログに戻す
- 修正は PR で行い、PR テンプレートのチェックリストを満たす
- 機能を足す・大きく変えるときは、先に `docs/specs/` に指示書を書く（`write-spec` スキル）
- 値や方針を変えたら ADR を足す（[`decisions/`](./decisions/README.md)）
- 見た目や構造化データを変えたら、プレビュー URL で確かめる

## 4. 再発を防ぐ（いちばん大事）

**直しただけで終わらせない。** 同じ種類の問題が二度と起きないよう、次のどれかを必ず足します。

| 問題の種類                                       | 足すもの                                                                 |
| ------------------------------------------------ | ------------------------------------------------------------------------ |
| 記事の frontmatter の誤り・抜け                  | Content Collections の Zod スキーマを厳しくする                          |
| JSON-LD・メタタグ・URL の誤り                    | 組み立てる関数の隣に `*.test.ts`、ビルド出力の検査スクリプトに項目を足す |
| クライアント JS が増えた・性能が落ちた           | 出力の検査で JS の量を制限する、Lighthouse CI の閾値を上げる             |
| 旧 URL の 404・リンク切れ                        | 旧 URL の一覧と内部リンクの検査に足す                                    |
| 記事の書き方のぶれ（見出し・画像・リンクカード） | `rules/content.md` に追記し、`write-post` スキルに手順を足す             |
| 判断基準のあいまいさ                             | `rules/*.md`・`AGENTS.md` に追記、または ADR                             |
| 手順の抜け・やり直し                             | `Makefile` のコマンドか `.cursor/skills/` のスキル                       |

どうしても仕組みにできないときは、`log.md` の「再発防止」に「—」と書き、理由をバックログに残します。

## 5. 振り返る

[`improvement/log.md`](./improvement/log.md) に 1 改善 1 行で記録します（新しいものを上に）。
ときどきログを見返し、同じ種類の改善が続いていれば、ルール文書や検査の仕組みそのものを見直します。見直した結果は ADR に残します。

## AI エージェントが回す場合

手順は [`.claude/skills/improve/SKILL.md`](../.claude/skills/improve/SKILL.md) にまとめています。エージェントは次の順で動きます。

1. `docs/improvement/backlog.md` と未解決の Issue を読み、優先度の高いものを 1 つ選ぶ（頼まれたものがあればそれ）
2. 関連する指示書・ADR・ルールを読んでから直す
3. 上の「再発を防ぐ」に従って検査やテストを足す
4. 検査が通ることを確かめ、`log.md` に 1 行足し、バックログから消して PR を出す

会話で指摘を受けて直したときも同じです。指摘の内容は `log.md` に残し、同じ指摘を二度受けないよう再発防止を足します。
