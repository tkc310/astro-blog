# 0023 記事（`src/content/`）は整形の検査から外す

- 日付: 2026-10-20
- 状態: 採用

## 背景

`make lint`（`vp check`）は、リポジトリのファイルが Oxfmt の整形どおりかを検査している。記事の Markdown も対象だった。

管理画面（Sveltia CMS、ADR-0004）は、保存のたびに記事のファイル全体を自分の形で書き直す。表の列をそろえず、入れ子の箇条書きを 4 文字下げる。Oxfmt の形とは違うので、表や入れ子の箇条書きがある記事を管理画面で保存するたびに CI が落ちた（PR #29・#38。2 回とも整形のコミットを足して直した）。

## 決定

- `vite.config.ts` の `fmt.ignorePatterns` に `src/content/**` を足し、記事・カテゴリ・自己紹介を整形の検査から外す
- 記事の形の検査は、これまでどおり Astro の Zod スキーマ（ビルド）と `make check-output` が行う。見た目に関わる規則（見出しのレベル、言語名、`alt` など）は `rules/content.md` のまま
- `make migrate` の最後の整形（`vp fmt src/content/posts`）をやめる。移行は終わっていて、再実行の予定は無い

## 理由

- 管理画面が記事を書く主な道具で、その出力の形はこちらで変えられない
- 表の列のそろえ方や箇条書きの字下げは、Markdown の描画結果（ページの表示）を変えない
- 管理画面の出力に毎回整形のコミットを足す（自動でも手でも）と、ボットのコミットで動く CI の承認や、保存のたびの手間が増える

## 影響・トレードオフ

- エディタで書いた記事と管理画面で書いた記事で、Markdown の見た目の形がそろわなくなる。そろえたいときは手で `oxfmt` をかけてよい（検査はしない）
- 検査を緩める変更なので、人の承認を得た（2026-10-20、案 A を選んでもらった）
