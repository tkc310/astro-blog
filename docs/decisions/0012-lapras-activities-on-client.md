# 0012 About の LAPRAS の活動一覧は、クライアントで取得して表示する

- 日付: 2026-10-19
- 状態: 採用

## 背景

旧ブログの About は、自己 PR と LAPRAS の活動一覧（GitHub・Zenn・Qiita・登壇などの記録）を表示していた。活動一覧はビルド時に `https://lapras.com/public/<share_id>.json` から取っていたため、次にビルドするまで古いままだった。

新しいブログはすべてのページをビルド時に作り、クライアント JS は目次とコードのコピーボタンだけにしている（[`rules/architecture.md`](../../rules/architecture.md)）。

## 決定

- About には自己 PR と、LAPRAS の活動一覧を載せる
- 活動一覧は、ブラウザで LAPRAS の公開 API を呼んで表示する。クライアント JS の例外として認める
- 一覧の場所は自己 PR の下に置き、取得前から高さを確保して、表示してもレイアウトがずれないようにする
- 一覧が画面に入ったときに取得を始める（IntersectionObserver）。取れなかったときは、LAPRAS のプロフィールへのリンクだけを出す
- 活動一覧は JSON-LD に入れない。ビルド時の HTML に無い内容だから（[`rules/seo.md`](../../rules/seo.md)）
- 呼ぶのは素の `fetch` で、UI フレームワークやライブラリは使わない

## 理由

- 活動はほぼ毎日増えるので、ビルドの時点で固定するより、開いたときの最新を見せたい
- 一覧はページの下の方にあり、About の主な内容（自己 PR）は静的な HTML のままなので、LCP や検索への影響は小さい

## 影響・トレードオフ

- LAPRAS の公開 API が、ほかのオリジンからの呼び出し（CORS）を許すかはドキュメントに無く、確かめていない。雛形で確かめる（バックログ）
- CORS が許されていなければ、次の順で代わりの手を選び、この ADR を見直す
  1. ビルド時に取得し、GitHub Actions の定期実行で毎日ビルドし直す（旧ブログに近い形）
  2. ブログの Worker で中継する（ブログの Worker にコードを書かない規則の例外になる）
- LAPRAS が止まったり形を変えたりすると、一覧が出なくなる。そのときもページの他の部分は壊れない
