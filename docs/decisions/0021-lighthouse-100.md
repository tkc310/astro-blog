# 0021 Lighthouse は 4 項目とも 100 点を目標にし、CI で守る

- 日付: 2026-10-20
- 状態: 採用

## 背景

これまでの目標は、Lighthouse（モバイル）で性能・SEO・アクセシビリティが 95 点以上だった。本番に切り替えたあと測ると、トップのアクセシビリティが 95（ページ送りの飾りのコントラスト不足）、記事の CLS が 0.118・0.134（スマホで目次を開いて出してから閉じていた）、トップの FCP が 2.0 秒（CSS の読み込みを待っていた）だった。直すと、測った 5 ページとも 4 項目が 100 点（性能は測るたびに 99〜100）になった。

## 決定

- 目標を、性能・アクセシビリティ・ベストプラクティス・SEO がすべて 100 点にする（`rules/seo.md`）
- CI（`lighthouserc.json`、3 回の中央値）は、アクセシビリティ・ベストプラクティス・SEO が 100 点、性能が 98 点、CLS が 0.01 以下、LCP が 2.5 秒以下でないと落ちる
- CSS は HTML に埋め込む（`build.inlineStylesheets: 'always'`）。どのページも CSS は 30KB 未満で、読み込みの往復を 1 回減らせる

## 理由

- アクセシビリティ・ベストプラクティス・SEO の点は、同じページなら測るたびに変わらない。100 点を下回るのは、何かを壊したときだけだ
- 性能の点は、CI の機械の混み具合で 1〜2 点揺れる。98 点にして、揺れでは落ちず、CLS や LCP の悪化は数値の検査で捉える

## 影響・トレードオフ

- CSS を埋め込むので、ページを移るたびに CSS も読み直す（ブラウザのキャッシュが効かない）。CSS が大きくなったら見直す
- 性能が 98〜99 点の変更は CI を通る。100 点でないことは、Lighthouse の報告（CI の成果物）で見る
