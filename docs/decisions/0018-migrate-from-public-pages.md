# 0018 移行のデータは microCMS の API ではなく、旧サイトの公開ページから取る

- 日付: 2026-10-19
- 状態: 採用

## 背景

ADR-0010 では、microCMS の API（API キーと下書きのキー）から記事を取る予定だった。移行の作業では API キーを使わず、公開している tkc310.com から取ることにした。

旧サイトは Next.js の静的生成（`getStaticProps`）で作られ、各ページの HTML に `__NEXT_DATA__` として、microCMS の応答（記事の本文の MDX のテキスト・カテゴリ・日付・抜粋）がそのまま入っている。HTML から本文を逆算する必要は無い。

## 決定

- `scripts/migrate-legacy.ts`（`make migrate`）で、トップと `/articles/page/<n>` の一覧から記事の ID を集め、各記事のページの `__NEXT_DATA__` を読む。サイトマップには全記事が載っていない（16 本中 10 本）ので使わない
- 変換は `docs/specs/microcms-migration.md` §2 のとおり。画像は `images.microcms-assets.io` からダウンロードしてリポジトリに置く
- 一度も公開していない下書きは公開ページに無いので移さない。必要なら、microCMS の管理画面から手で移す
- 旧ブログのカテゴリには色が入っていない（空の配列）ので、移行のときに決める（スクリプトの `CATEGORY_COLORS`）
- ADR-0010 の残り（一度きりのスクリプト、画像の移し方、切り替えの手順）はそのまま

## 理由

- API キーをこのリポジトリの作業環境に置かずに済む
- `__NEXT_DATA__` は microCMS の API の応答と同じ形なので、取れる情報は公開済みの記事について API と変わらない
- 公開ページから取るので、本番に出ている版（＝移すべき版）と食い違わない

## 影響・トレードオフ

- 旧サイトの作り（Next.js の `__NEXT_DATA__`）に頼る。旧サイトを消したら再実行できない。切り替えの直前の再実行（`microcms-migration.md` §6 の 2）は、旧サイトを消す前に行う
- 未公開の下書きは移らない
