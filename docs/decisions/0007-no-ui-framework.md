# 0007 UI フレームワークを入れず、Astro コンポーネントと scoped CSS で作る

- 日付: 2026-10-19
- 状態: 採用

## 背景

旧ブログは Chakra UI v1・Emotion・framer-motion・react-icons・SCSS・tocbot を使い、メニュー・目次・リンクカード・画像の遅延読み込みをクライアントの React で動かしていた。これが JS の量と CLS を増やしていた。

## 決定

| 用途         | 使うもの                                                                       |
| ------------ | ------------------------------------------------------------------------------ |
| UI 部品      | Astro コンポーネントだけ。React などの UI フレームワークとアイランドは入れない |
| スタイル     | コンポーネントの `<style>`（scoped CSS）と、`:root` の CSS 変数のトークン      |
| 本文の組版   | 自前の `prose.css`                                                             |
| メニュー     | `popover` 属性か `<dialog>`                                                    |
| 目次         | ビルド時に見出しから作り、現在位置の強調だけ小さなスクリプト                   |
| アイコン     | astro-icon（ビルド時に SVG を埋め込む）                                        |
| フォント     | 日本語はシステムフォント。等幅だけ Astro の Fonts API で読む                   |
| ページ遷移   | CSS の `@view-transition`（JS を使わない）                                     |
| ダークモード | `prefers-color-scheme` に従う（切り替えボタンは置かない）                      |

## 理由

- ブログに必要な動きは、ほとんど HTML と CSS だけで作れる。クライアント JS を減らすと LCP と INP が良くなる
- scoped CSS は依存が無く、コンポーネントと同じファイルにあるので、人もエージェントも追いやすい
- Tailwind CSS v4 と Panda CSS も検討した。部品の数が少ないブログでは、道具を増やすほどの得が無い
- 日本語の Web フォントは容量が大きく、LCP と CLS を悪くしやすい

## 影響・トレードオフ

- 動きの多い UI（検索など）を足すときは、ページ単位で読み込む素の JS にする。UI フレームワークを入れるなら ADR を足す
- クライアント JS の上限は [`rules/architecture.md`](../../rules/architecture.md) に書く
