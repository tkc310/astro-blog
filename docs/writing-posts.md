# 記事の投稿手順と注意点

記事を書いて公開するまでの手順です。形式の規則は [`rules/content.md`](../rules/content.md) が正本で、ここはその使い方をまとめます。

記事は `src/content/posts/<id>.md` の Markdown で、`main` にマージされたものが本番に出ます。書き方は 2 通りあり、どちらでも最後は Pull Request（PR）をマージして公開します。

| 書き方                   | 向いているとき                                       |
| ------------------------ | ---------------------------------------------------- |
| A. 管理画面（`/admin/`） | ブラウザだけで書きたい。画像をドラッグで足したい     |
| B. エディタと Git        | コードの多い記事。手元で見た目を確かめながら書きたい |

## A. 管理画面で書く

1. [https://tkc310.com/admin/](https://tkc310.com/admin/) を開き、「GitHub でサインイン」する
2. 「記事」→「新しい記事」を押す
3. 項目を埋める
   - **ID（ファイル名）**: URL（`/articles/<id>`）になる。英小文字・数字・`-` だけ（例: `astro-cloudflare-migration`）。**公開したら変えない**
   - **タイトル**: 110 字以内
   - **説明**: 120 字前後で要点を 1〜2 文。検索結果・SNS・AI の要約に使われる
   - **公開日**・**カテゴリ**
   - **下書き**: 書き終わるまでオンにしておく
   - **本文**: Markdown（下の「本文の書き方」）
4. 保存する。Editorial Workflow なので `main` には直接入らず、記事ごとのブランチと PR ができる
5. PR に Cloudflare Workers Builds がプレビュー URL をコメントするので、そこで見た目を確かめる。プレビューでは下書きも表示される
6. 公開するときは、下書きをオフにして保存し、状態を「Ready」にして「公開」する（PR がマージされる）。数分で本番に出る

## B. エディタと Git で書く

```bash
git switch main && git pull
git switch -c post/<id>
SHOW_DRAFTS=true make dev     # http://localhost:4321 で下書きも見える
```

1. `src/content/posts/<id>.md` を作る

   ```md
   ---
   title: 記事のタイトル
   description: 記事の要点を 1〜2 文、120 字前後で書く。
   pubDate: 2026-10-20T09:00:00+09:00
   category: tech
   draft: true
   ---

   ## はじめに

   本文…
   ```

   - `category` は `src/content/categories/` のファイル名（`tech`・`lifehack`・`book_review`・`occult`・`etc`）
   - frontmatter に書けるのは `title`・`description`・`pubDate`・`category`・`updatedDate`・`draft` だけ。ほかの項目を書くとビルドが落ちる

2. 画像は `src/assets/posts/<id>/` に置き、本文から相対パスで参照する。スマホの写真は幅 1600px までに縮めてから置く
3. `make check` を通す
4. `post` の type でコミットして PR を出す（例: `post: Astro 7 への移行メモを公開する`）
5. プレビュー URL で確かめ、`draft: true` を外すコミットを足してマージする

## 本文の書き方

| 書きたいもの   | 書き方                                                                                                           |
| -------------- | ---------------------------------------------------------------------------------------------------------------- |
| 見出し         | `##` から始める（`#` はタイトル専用）。レベルを飛ばさない（`##` の次に `####` は不可）。`##`・`###` が目次になる |
| リンクカード   | URL だけを 1 行に書き、前後を空行で挟む。文中のリンクは `[テキスト](URL)`。箇条書きの中の URL はカードにならない |
| 画像           | `![何が写っているか](../../assets/posts/<id>/image.png)`。`alt` を必ず書く                                       |
| コード         | ` ```ts ` のように言語名を付ける。ファイル名は ` ```ts title="src/foo.ts" `                                      |
| 強調・表・引用 | ふつうの Markdown（GFM）                                                                                         |

リンクカードの例:

```md
次の記事が参考になりました。

https://docs.astro.build/ja/guides/content-collections/

続き…
```

## 注意点

### 公開前

- **ID は公開したら変えない。** URL が変わり、検索やリンクからの流入が切れる。どうしても変えるときは `public/_redirects` に 301 を足す
- **下書き（`draft: true`）は本番に出ない。** サイトマップ・RSS・一覧にも入らない。プレビュー URL と `SHOW_DRAFTS=true make dev` でだけ見える
- **`description` は手を抜かない。** 検索結果とシェアのカードに出る。本文の書き出しのコピーではなく、記事の要点を書く
- **MDX や HTML のタグで見た目を作らない。** JSX の部品は使えない
- **外部の画像の URL を本文に書かない。** 画像はリポジトリに置く（大きさの指定と最適化がビルドで付く）

### リンクカード

- カードのタイトル・説明・画像は、**ビルドのたびに**リンク先の OGP から取る。リンク先が消えたり 10 秒以内に応答しなかったりすると、カードにならずふつうのリンクになる（ビルドは止まらない）
- カードの画像はこのサイトから配信する。リンク先が後で画像を変えると、次のビルドで変わる

### 公開後

- 中身を大きく直したら `updatedDate` を足す（記事の「更新」の日付と、構造化データの `dateModified` に使われる）。誤字の修正だけなら足さない
- 記事を消すときは、ファイルを消して `public/_redirects` に `/articles/<id> / 301` を足す（消した URL を 404 にしない）
- カテゴリを足すときは、管理画面の「カテゴリ」か `src/content/categories/<id>.yml`（`name`・`color`）で足す。ID は URL（`/articles/categories/<id>`）になるので、これも変えない

### 困ったとき

| 症状                         | 見るところ                                                                                                             |
| ---------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| PR のビルドが落ちる          | CI の check のログ。frontmatter の項目名・`category` の綴り・見出しのレベルが多い                                      |
| 本番に出ない                 | `draft: true` が残っていないか。PR がマージされたか                                                                    |
| リンクカードにならない       | 前後に空行があるか。URL だけの行か。リンク先が OGP を返すか                                                            |
| 画像が出ない                 | パスが `src/assets/posts/<id>/` を指しているか。ファイル名の大文字・小文字                                             |
| 管理画面にサインインできない | 認証の Worker（`astro-blog-sveltia-cms-auth`）と GitHub の OAuth App の設定（`public/admin/config.yml` の `base_url`） |

AI エージェントに記事を書かせるときは、`.claude/skills/write-post/SKILL.md` の手順に従わせます。
